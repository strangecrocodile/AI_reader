# AI讲师 后端设计文档

## 1. 定位与范围

后端负责「教材驱动的学习系统」的服务端能力，与前端 `frontend/src/services/api.js`
的接口约定一一对应。当前实现覆盖产品文档 MVP 主链路：

> 导入教材（PDF / Word / 纯文本）→ 解析章节 → 生成学习路径 → 查看章节讲解 → 溯源问答 → 知识图谱

**录入范围**：文本型 PDF（可含目录书签）、Word `.docx`（按标题样式识别章与节）、
纯文本 `.txt` / Markdown `.md`。扫描件、复杂 OCR 与手写内容不纳入（产品文档 6 节明确
列出范围边界）；旧版 `.doc` 需另存为 `.docx`。

三种格式解析后产出**同一套章节-段落-锚点模型**，下游（检索、问答、知识点图谱）不区分来源格式。

## 2. 技术栈与开源资源

| 职责 | 组件 | 开源许可 | 团队自主实现部分 |
|---|---|---|---|
| 后端框架 | FastAPI + Uvicorn | MIT | — |
| PDF 解析 | PyMuPDF | AGPL-3.0 | 章节/段落/锚点结构提取、标题启发式、页码过滤 |
| Word 解析 | python-docx | MIT | 大纲层级判定章/节、虚拟页码、与 PDF 共用锚点模型 |
| 纯文本解析 | Python 标准库 | 公有领域 | Markdown 标题层级、中文「第X章」文本模式、GB18030 编码探测 |
| 检索 | 自实现 BM25 | Apache 2.0（代码自主） | 中文二元组分词、BM25 打分、覆盖率反幻觉判定 |
| 知识点抽取与图谱 | 自研（契约对齐 `tools/kb-agent` V2） | 代码自主 | 抽取提示词、规则回退、跨章概念合并、前置关系与未解析前置 |
| 向量检索（可选） | OpenAI 兼容 /embeddings（如 SiliconFlow BGE-M3） | 模型 MIT | 混合检索融合逻辑 |
| 大模型 | 云端开源模型 API（DeepSeek / Qwen 等，OpenAI 兼容） | 视供应商 | 提示词约束、引用校验、JSON 解析与回退 |
| 存储 | SQLite（标准库） | 公有领域 | 存储层设计 |

设计原则：**无 API Key 时后端照常运行**（规则 mock 回退），演示与测试不依赖外部服务。

## 3. 模块结构

```
backend/
├── app/
│   ├── main.py            # create_app：装配 db / llm / retrieval（测试可注入）
│   ├── config.py          # 环境变量配置（LLM_BASE_URL / LLM_API_KEY / …）
│   ├── db.py              # sqlite3 存储层（书/章/段落/锚点/讲解/路径/知识点/事件/线程）
│   ├── models.py          # Pydantic 请求模型（AskRequest）
│   ├── serializers.py     # 数据库行 → 前端约定的 JSON（书/章节内容）
│   ├── parsing/
│   │   ├── base.py        # 共享结构：ParsedBook、章/节标题模式、层级判定、虚拟页码
│   │   ├── pdf.py         # PDF 解析（目录书签 + 标题启发式 + 段落切分）
│   │   ├── docx.py        # Word 解析（标题样式层级 + 文本模式兜底）
│   │   └── text.py        # txt / md 解析（Markdown 标题 + 中文章标题 + 编码探测）
│   ├── rag/
│   │   ├── bm25.py        # 自实现 BM25（CJK 二元组分词）
│   │   ├── vector.py      # 可选：云端嵌入向量检索（余弦，按书建一次）
│   │   └── retrieval.py   # 混合检索 + 本章/全书范围（search_scoped）
│   ├── llm/
│   │   ├── client.py      # CloudLLM（OpenAI 兼容）/ MockLLM（规则回退）
│   │   └── prompts.py     # 备课 / 问答 / 规划 / 知识点抽取提示词（引用约束）
│   ├── services/
│   │   ├── ingest.py      # 多格式分派 → 解析 → 入库（生成锚点）
│   │   ├── lesson.py      # 章节备课讲解（缓存）
│   │   ├── ask.py         # 溯源问答（跨章检索 + 生成 + 反幻觉 + SSE 流式）
│   │   ├── threads.py     # 追问线程（围绕选中原文的持续问答）
│   │   ├── plan.py        # 学习路径（缓存）
│   │   ├── progress.py    # 学习事件 → 掌握度（可解释公式，含拆分说明）
│   │   ├── concepts.py    # 知识点抽取（LLM + 规则回退）与概念图谱构建
│   │   └── knowledge.py   # 知识地图聚合（概念节点 + 前置关系 + 未解析前置）
│   └── routers/books.py   # REST 路由（含 SSE）
├── scripts/make_demo_pdf.py  # 生成原创示例教材（版权合规）
└── tests/                 # pytest（125 项）
```

## 4. API 约定（与前端对接）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查（含 LLM 模式） |
| GET | `/api/books` | 教材列表（含章节、学习计划） |
| GET | `/api/books/{id}` | 单本教材 |
| POST | `/api/books` | 上传教材（multipart `file` + 可选 `title`）：支持 `.pdf` / `.docx` / `.txt` / `.md` → 解析入库 |
| GET | `/api/books/{id}/chapters/{cid}` | 章节内容：原文段落（锚点）+ AI 讲解 + 知识点大纲 |
| GET | `/api/books/{id}/knowledge` | 知识图谱 v2：跨章概念节点 + 前置关系 + 学习顺序 + 未解析前置 + 统计 |
| POST | `/api/books/{id}/chapters/{cid}/events` | 上报学习事件（`open` / `read` / `ask` / `complete` / `quiz`）→ 重算并返回掌握度与拆分说明 |
| POST | `/api/books/{id}/chapters/{cid}/progress` | **手动覆盖**章节进度（调试/纠偏用），正常学习进度走 `/events` |
| POST | `/api/ask` | `{question, bookId, chapterId, selectedText?, threadId?}` → `{answer, sources, sourceDetails, scope, threadId}` |
| POST | `/api/ask/stream` | 同上，返回 SSE：`meta`（检索范围与证据）→ `delta`（逐块回答）→ `done`（完整回答 + 溯源锚点） |
| POST | `/api/threads` | 新建追问线程：`{bookId, chapterId, anchorId?, selectedText?}` |
| GET | `/api/books/{id}/chapters/{cid}/threads` | 本章追问线程列表（最近追问在前） |
| GET | `/api/threads/{id}` | 单条线程（含全部消息） |
| DELETE | `/api/threads/{id}` | 删除线程（连带消息） |
| POST | `/api/books/{id}/plan` | 生成/重新生成学习路径 |

前端通过 `VITE_API_BASE_URL`（见 `frontend/.env.example`）切换后端模式；
未配置时前端使用内置演示数据。

## 5. 溯源问答（核心链路）

```
question
   │
   ├─ ① 本章检索（BM25 + 可选向量融合）
   │      └─ 本章最佳命中覆盖率 ≥ 0.22 ──► scope = chapter
   │
   ├─ ② 本章依据不足 ──► 扩展到全书检索（同一套 BM25/向量，允许列表放到整本书）
   │      └─ 命中可能来自其他章节 ──► scope = book
   │
   ├─ 覆盖率仍 < 0.22 ──► 「教材中未找到直接依据」（不编造）
   │
   └─ 有证据 ──► 提示词（片段编号 [1][2]…，标注章节名）
                 │
                 ├─ 非流式：一次生成
                 └─ 流式（/api/ask/stream）：meta → delta* → done
                 │
                 ▼
        溯源锚点由回答里的 [n] 反查证据得出（不信任模型自报 id）；
        没有引用则回退到第一条证据
                 │
                 ▼
        {answer, sources:[锚点id], sourceDetails:[{id, page, text, chapterId, chapterTitle}], scope}
```

- 锚点 id 与段落 id 相同（如 `b1-s2-9`），前端同章直接定位高亮；
- `sourceDetails` 带 `chapterId` / `chapterTitle`，**跨章依据**由前端跳到对应章节再定位；
- `scope=book` 表示「本章没讲清楚，答案依据来自全书检索」，前端会显示提示；
- 章节重新导入会调用 `retrieval.invalidate_book` 清掉该书的 BM25/向量缓存；
- **无模型 / 模型调用失败时不做生成**：兜底答案只列检索到的教材原文（逐条带 `[n]` 编号，
  仍可溯源回跳），并注明当前未接入大模型。**不返回与教材无关的通用讲解**——这条和
  「教材中未找到直接依据」是同一条产品边界（见 `产品设计文档.md` 第 4.4 节），
  兜底路径同样不许越过。

## 6. 知识图谱（概念层 v2）

契约与 `tools/kb-agent` 的 `extract.py` / `graph.py` 对齐（该组件依赖 LangChain 等重型
依赖、独立虚拟环境，后端这里自研轻量实现，**不引入它的依赖**）：

```
章节锚点段落 ──► LLM 结构化抽取 {concept, definition, prerequisites, example, anchors}
             │     （anchors 只能取本章真实锚点，禁止编造；每章 ≤12 条）
             ├─ 无 Key / 输出非法 ──► 规则回退（强标记词定位定义句，确定性可测）
             ▼
        concepts 表按 (book_id, chapter_id) 缓存（只抽取一次）
             │
             ▼
   跨章按概念名合并节点 ──► 前置边（source 依赖 target）
                       ├─► 同章相邻概念补「学习顺序」边（已有前置边则不重复）
                       └─► 找不到的前置概念归入 unresolved（前端标为教材外）
```

`GET /api/books/{id}/knowledge` 返回：

| 字段 | 说明 |
|---|---|
| `concepts[]` | 节点：`id/title/label/definition/summary/prerequisites/chapters/anchorCount/anchors/chapterId/chapterTitle/sourceId/sourceLabel/status/mastery/method` |
| `relations[]` | 边：`{id, source, target, type: prerequisite\|sequence, label}` |
| `unresolved[]` | `{name, requiredBy[]}` —— 前置概念在本教材里找不到（表述差异或未入库章节） |
| `methods` | 本次图谱用到的抽取方式：`llm` / `rule` |
| `stats` | `conceptCount / learnedCount / relationCount / prerequisiteCount / unresolvedCount` |

其中 `title/summary/chapterId/chapterTitle/sourceId/status/mastery` 是升级前的兼容字段，
前端可零改动读取；`sourceId` 一定是该章真实存在的锚点，保证节点能回跳教材原文核对。

## 7. 掌握度计算（可解释）

掌握度**不是前端写死的数字**，而是由学习事件算出来的：

```
open（进入章节） / read（读到段落，带锚点 id） / ask（提问，记问题原文）
complete（标记学完） / quiz（自测作答，带对错）
        │  写入 learning_events（read 按锚点去重、ask 记原文用于去重）
        ▼
services/progress.py 按公式重算
        │
        ▼
chapter_progress（只增不减） ──► 知识点卡片掌握度 / 教材总进度（各章平均）
```

| 分项 | 定义 | 权重 | 防刷分约束 |
|---|---|---|---|
| 覆盖度 | 读过的正文段落数 / 本章正文段落总数 | 50 | 只认本章真实锚点，乱报不计分 |
| 互动度 | min(不同提问数, 5) / 5 | 25 | 同一问题只算一次，封顶 5 次 |
| 自测正确率 | 答对题数 / 答题总数 | 25 | 无自测记录时该项权重按比例并入前两项（覆盖度 66.7 / 互动度 33.3） |

- 状态规则：`complete` 事件或掌握度 ≥ 80 → `learned`；有任意事件 → `learning`；否则 `planned`；
- 掌握度只增不减（`chapter_progress` 取 max），因此接口同时返回
  `computed`（本次按事件算出的值）与 `mastery`（实际生效值）；
- `/events` 返回值含 `breakdown`（每项的权重与得分）与 `signals`（读了几段、提问几次…），
  前端据此展示「掌握度是怎么来的」；前端演示模式用 `frontend/src/services/progress.js` 实现同一套公式。

## 8. 追问线程（划词气泡的持久化）

一次划词 = 一条线程：气泡里的所有追问都落在同一条线上，刷新页面 / 切回章节仍可回看。

```
选中原文（带锚点 id）
   │  POST /api/threads
   ▼
threads(id, book_id, chapter_id, anchor_id, selected_text, created_at, updated_at)
   │  POST /api/ask(/stream) + threadId
   ▼
thread_messages(thread_id, role, text, sources, detail{sourceDetails, scope}, created_at)
```

约定：

- 线程绑定 `(book, chapter, 锚点, 选中原文)`；**带 `threadId` 提问时检索范围以线程所属章节为准**
  （防止把线程的追问算到别的章节头上）；
- 流式提问先落「问题」再生成（流断也不丢问题），收尾落「回答」；
- 标题：优先取选中原文（截断 24 字），否则取第一个问题；
- 气泡位置、拖动状态由前端管理，**不入库**（见 `docs/下一阶段开发文档.md` 第 4 节约束）；
- `updated_at` 为微秒精度，保证「最近追问」排序可区分。

## 9. 运行与测试

```powershell
cd backend
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe scripts\make_demo_pdf.py        # 生成原创示例教材
.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
.venv\Scripts\python.exe -m pytest                       # 125 项测试
```

配置真实模型：复制 `.env.example` 为 `.env` 并填写 `LLM_BASE_URL` / `LLM_API_KEY`。
不配置时 `llm=mock`，讲解/问答/知识点抽取全部走规则回退，链路仍可完整演示。
