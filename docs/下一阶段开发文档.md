# 下一阶段开发文档

## 1. 目标

下一阶段的目标不是把所有功能一次做满，而是先把“教材学习闭环”做成一个稳定的 MVP：

1. 首页能看到当前学习教材与当前学习计划。
2. 学习页能完成 PDF 阅读、划词提问、气泡追问、AI 讲义查看。
3. 知识页能沉淀已学知识点卡片与关系图谱。

核心原则：

- 事实层以 RAG 为底座，保证回答能回到教材原文。
- 讲义层可以做成 LLM wiki，但它是“知识沉淀层”，不是唯一真相来源。
- Agent 负责编排学习动作，不直接控制 UI 坐标和复杂前端状态。

## 3. 页面目标

### Home 页面

- 左侧：当前学习中的教材。
- 右侧：当前学习计划。
- 目标是让用户“一眼知道现在学哪本书、下一步学什么”。

### Study 页面

- 左侧：PDF 阅读器。
- 支持文本高亮、左键选中、定位原文。
- 选中文本后，在选区旁边弹出 AI 气泡。
- 气泡可拖动，可继续追问。
- 右侧：AI 讲义，展示知识点清单和每个知识点的解释。
- 下半部分：可切换为知识卡片和笔记区。

### Knowledge 页面

- 展示已学习的知识点卡片。
- 展示知识点关系图谱，类似 Obsidian 的关系视图。
- 节点要能回链到教材页、讲义卡片和笔记。

## 4. Agent 设计

建议采用“一个总调度器 + 四个窄职责 Agent”的结构。

| Agent | 职责 | 输入 | 输出 |
|---|---|---|---|
| Orchestrator | 判断当前请求走问答、规划、抽取还是回写 | 页面事件、线程状态、用户操作 | 路由决策 |
| Tutor | 负责解释教材、回答追问、给出气泡内容 | 选中文本、章节上下文、检索结果 | 可追溯回答 |
| Planner | 负责首页学习计划与章节推进建议 | 教材结构、掌握度、历史学习记录 | 学习计划 |
| Curator | 负责知识点卡片、讲义摘要、题目、笔记草稿 | 章节内容、知识点、问答记录 | 结构化学习产物 |
| Indexer | 离线解析教材、切 chunk、抽知识点、建关系 | PDF/章节/段落 | 索引、图谱、知识点节点 |

设计约束：

- Agent 输出尽量结构化，优先 JSON。
- UI 坐标、浮层位置、拖拽状态由前端管理。
- 每次回答都要附带来源锚点，不能只给“看起来像对的”解释。
- 一轮问答的上下文要绑定到 `thread_id`，不要退化成全局聊天。

## 5. 知识底座设计

建议把知识底座拆成三层：

### 5.1 RAG 事实层

用途：

- 划词问答
- 章节解释
- 原文依据回跳

特点：

- 只回答教材里能找到依据的问题。
- 如果证据不足，明确说“教材中未找到直接依据”。

### 5.2 LLM Wiki 概念层

用途：

- 生成知识点长文讲解
- 维护“概念页”
- 形成稳定的知识沉淀

特点：

- 适合展示与沉淀。
- 不适合直接充当事实检索的唯一来源。
- 需要和原文锚点、章节页码保持关联。

### 5.3 图谱关系层

用途：

- 记录前置、包含、相关、对比、例题依赖等关系
- 支撑 Knowledge 页面可视化

特点：

- 图谱不是摆设，节点必须能回到教材、讲义、笔记。
- 先做“可读、可点、可回跳”，再追求复杂算法。
- **已完成**：前置依赖已落地——知识点抽取产出 `prerequisites`，后端跨章合并为概念节点并生成
  「前置」语义边，同时保留同章「学习顺序」边作为离线兜底；教材里找不到的前置单列 `unresolved`。
  实现见 `docs/后端设计文档.md` 第 6 节（契约与 `tools/kb-agent` 的 V2 概念层对齐）。

## 6. 数据模型建议

在现有 `books / chapters / sections / anchors / explanations / plans` 之上，下一阶段建议补这些实体：

- `concepts`：知识点节点。**已实现**
- `relations`：知识点之间的关系。**已实现**（前置 / 学习顺序）
- `threads`：围绕某段原文的追问线程。**已实现**（含 `thread_messages`）
- `cards`：知识卡片。
- `notes`：用户笔记。
- `questions`：系统生成题目与用户作答记录（已预埋 `quiz` 学习事件）。
- `mastery`：知识点掌握度。**已实现**（由学习事件算出，见后端设计文档第 7 节）

推荐先继续沿用 SQLite，把结构先跑通；等数据量和检索需求上来，再考虑向量库或独立图数据库。

## 8. 重点风险

1. 不要先做“一个会自己思考很久的大 Agent”，容易失控。
2. 不要先做完整 wiki 代替 RAG，容易丢证据。
3. 不要一开始就引入太多存储和检索组件，容易拖慢开发。
4. 不要把知识图谱做成纯装饰图，节点必须服务学习动作。

## 9. 成功标准

- 用户能在首页选书，在学习页完成阅读、划词、追问、回看。
- AI 回答能清晰落到教材原文。
- 已学知识点可以沉淀成卡片与图谱。
- 系统能稳定支撑一个月内的演示版本。

## 11. 开源支撑选型（本轮讨论结论）

### 11.1 结论

下一阶段**不**引入整平台型 RAG 产品（Dify / RAGFlow）作为主底座——那更容易触碰赛题“不得仅通过组合现成工具形成作品”的边界，也会把检索核心变成黑盒。
保留自研 **BM25 + 混合检索** 作为**事实层**（团队自主实现、可解释、可测试），仅在三个明确缺口上引入开源组件，LLM 统一走 DeepSeek：

| 缺口 | 候选开源项目 | 许可 | 提供的支撑 | 建议 |
|---|---|---|---|---|
| 知识图谱**可视化**（现为简易网格布局） | [react-force-graph](https://github.com/vasturiano/react-force-graph) | MIT | d3 力导向布局，节点可拖/缩放/点击，便于回链 | ✅ 采用，替换现有 `KnowledgePage` 网格 |
| 知识图谱**可视化**（备选） | [@neo4j-nvl](https://www.npmjs.com/package/@neo4j-nvl/base) | Apache-2.0 | 图可视化，交互性强 | 备选 |
| 知识图谱**可视化**（备选，更稳/零额外依赖） | [vis-network](https://github.com/visjs/vis-network) / cytoscape.js | MIT | 成熟、文档全 | 备选 |
| 知识图谱**构建**（实体/关系抽取） | [Microsoft GraphRAG](https://github.com/microsoft/graphrag) | MIT | 从长文本抽取实体与关系、社区分层 | ⚠️ 实验性：偏重、成本高，MVP 先不依赖 |
| 检索/编排**抽象**（可选） | LlamaIndex / LangChain | MIT | chunk、索引、Agent 编排 | 可选；当前自研已够，暂不引入 |
| 出题 / 评测（可选） | 视具体项目再定 | — | 生成题目与判分 | P2 再评估 |

**LLM**：确定接入 **DeepSeek（OpenAI 兼容）**，走现有 `CloudLLM`（`app/llm/client.py` 已预留 `LLM_BASE_URL` / `LLM_API_KEY` 配置，见 `config.py`）。未配置时自动 `MockLLM` 回退，保证演示与测试不依赖外部服务。

### 11.2 视觉层落地（P0 之一）

用 react-force-graph（或备选）替换现有网格图谱：节点与连边直接消费后端 `/knowledge` 返回的 `concepts` 与 `relations`，保留「点节点 → 看详情 → 回教材原文 `sourceId`」这条回链。
先做“可读、可点、可回跳”，不追求复杂布局算法，避免为好看的图而做无意义的装饰。

> 进度：数据侧已就绪——`/knowledge` 已返回跨章概念节点、`prerequisite` / `sequence` 两类关系与
> `unresolved` 前置；当前网格布局里前置依赖画实线带箭头、学习顺序画虚线。
> 剩余待办是**换布局**（力导向），不再需要动数据契约。

### 11.3 合规与披露

- PyMuPDF 为 **AGPL-3.0**：仅用于后端内部解析，不对外分发修改后版本，仍需在《开源及第三方资源使用清单》如实披露。
- GraphRAG、react-force-graph 等新引入组件，均需在《开源及第三方资源使用清单》登记版本、许可与使用方式。
- 若修改了引入组件的源码，须满足对应许可义务（MIT / Apache 允许，须保留版权声明）。

### 11.4 一个可后置的战略决策点

赛题方向（三）《开源项目改进与生态贡献》意味着：也可**选一个现有的开源“教材 AI 助教”项目作为底座做二次开发**，替代或拼接自研主链路。
若走这条路，“可溯源问答 + 知识图谱 + 掌握度”可作为相对原项目的**实质改进**来申报。

当前判断：自研主链路已能完整演示，按方向（一 / 四）申报 + 如实披露开源组件更稳；
方向（三）作为加分备选，需在本轮讨论之后单独决策。
